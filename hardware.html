How Parts Connect

부품 관계도

카메라는 출구마다 흩어져 있고 AI 박스는 기계실 한곳에 있습니다. 영상은 AI 박스에서 끝나고, 밖으로는 인원 수만 나갑니다.

전원 영상 (랜선) 영상 (광케이블) 인원 수 (MQTT) 제어 신호

카메라 수(6대 / 4대)는 예시입니다. 어느 출구가 100m를 넘는지는 역 도면과 현장 조사로 정합니다. 파란 선(영상)은 랜선이든 광케이블이든 Jetson에서 끝나고, 그 오른쪽으로는 초록 선(인원 수)만 이어집니다. 출구 쪽 스위치는 출구 근처 콘센트에서 전원을 받으므로, 정전 대비가 필요하면 출구 쪽에도 소형 UPS를 둡니다.

SBC · MCU Selection

SBC는 Jetson, MCU는 Pico로 고릅니다

SBC(싱글 보드 컴퓨터)는 영상 처리를 전부 맡고, MCU(마이크로컨트롤러)는 SBC가 멈췄을 때 되살리는 일만 합니다. 병목은 YOLO 추론뿐 아니라 영상 10개를 동시에 디코딩하는 것이라, 추론·디코딩·코드 호환 셋 중 하나라도 못 맞추면 탈락입니다.

Hardware Watchdog

Jetson이 멈추면 MCU가 되살립니다

Linux는 커널·드라이버·메모리 부족으로 멈출 수 있지만, MCU는 구조가 단순해 거의 멈추지 않습니다. 이 시스템에는 모터가 없으므로 MCU에 맡길 "절대 죽으면 안 되는 일"은 SBC를 감시하고 되살리는 일입니다.

전원 제어 신호

MCU 전원은 릴레이 앞에서 받습니다. Jetson 전원을 끊어도 MCU는 켜져 있어야 다시 켤 수 있기 때문입니다. 릴레이는 상시 닫힘(NC)이라 MCU가 고장 나거나 꺼져도 Jetson 전원은 유지됩니다. 핀 위치·전류는 데이터시트로 다시 확인합니다.

가벼운 방법부터, 안 되면 다음 단계로
  1. 1컨테이너 하나가 죽음 — Docker가 그 컨테이너만 재시작
  2. 2Docker 전체가 응답 없음 — watchdog 컨테이너가 하트비트를 멈춤
  3. 3Linux 커널 멈춤 — Jetson 내장 워치독이 리셋
  4. 4하트비트 3분 넘게 없음 — MCU가 리셋 핀을 잠깐 당김
  5. 5리셋 뒤 5분 안에 안 돌아옴 — MCU가 릴레이로 19V를 10초 끊었다 다시 연결
  6. 65단계를 3번 해도 실패 — 더 반복하지 않고 대기, 현장 점검 대상 (부품 손상 방지)

리셋·전원 재투입 횟수는 다음 부팅 때 MCU가 Jetson에 알리고, 상태 정보에 실려 클라우드로 갑니다. 시간 값은 vision 재시작·TensorRT 엔진 로드 실측으로 조정합니다.

Inference Engine

추론 엔진은 ONNX Runtime을 씁니다

후보는 ONNX Runtime · NCNN · OpenVINO · TFLite(LiteRT) 네 가지입니다. Jetson 성능은 대부분 GPU에서 나오는데, 네 엔진 중 Jetson의 GPU를 쓸 수 있는 것은 ONNX Runtime뿐입니다.

ONNX Runtime 채택
Jetson에서는 실행 공급자를 아래 순서로 지정합니다. 되는 연산은 앞쪽에서, 안 되는 연산은 다음으로 넘겨 전체가 멈추지 않습니다.
  1. 1TensorRT — Tensor 코어, FP16·INT8
  2. 2CUDA — TensorRT가 못 하는 연산
  3. 3CPU — 마지막 대체 (개발 PC도 이 경로)

ultralytics는 CUDA까지만 ultralytics로 .onnx를 열면 CUDA → CPU만 켭니다. TensorRT 속도가 필요하면 ONNX Runtime 세션을 직접 여는 검출기를 Detector 인터페이스로 추가합니다.

Jetson용 wheel 설치 PyPI의 일반 onnxruntime-gpu가 아니라 JetPack · Python · CUDA 버전에 맞는 Jetson용 wheel을 설치합니다.
기존 TensorRT 계획과의 관계

ONNX Runtime + TensorRT 실행 공급자는 안에서 같은 TensorRT를 쓰면서, 지원되지 않는 연산의 대체 실행과 개발 PC와 같은 모델 파일을 더한 방식입니다. Jetson 실측에서 TensorRT 직접 실행(.engine)과 속도 차이가 작으면 ONNX Runtime으로 통일하고, 초당 100프레임을 못 맞추면 TensorRT 직접 실행을 씁니다.

보드를 바꾸면 엔진도 바뀝니다: RK3588 → RKNN, Hailo → HailoRT, 라즈베리파이 단독 → NCNN, Intel 미니 PC → OpenVINO. 전체 내용은 저장소의 report/inference_engine.md에 있습니다.

  • · 비밀값은 .env · 인증서 볼륨으로만 — Git과 이미지에 키가 들어가지 않습니다
카메라 10대는 컨테이너 몇 개로?
A. 카메라마다 컨테이너 지금 코드 그대로, 하나가 죽어도 나머지는 무사. 대신 모델·CUDA를 10번 올려 8GB 공유 메모리가 모자랄 수 있습니다.
B. 컨테이너 하나에 여러 대 모델을 한 번만 올리고 배치 추론. 여러 카메라를 받는 실행 스크립트가 새로 필요합니다.
권장 — A로 2~3대 띄워 메모리를 재고, 10대에서 모자라면 B(3~4대씩 묶은 컨테이너 2~3개)로 갑니다.
