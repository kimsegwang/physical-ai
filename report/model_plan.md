# 모델 선정 · 학습 · 검증 계획

> 지하철 개찰구 혼잡도 예측 시스템의 모델 선정 근거, 학습 계획, 검증 방법을 정리한 문서.

## 0. 현재 상태

- **학습은 아직 하지 않았다.** COCO로 사전학습된 YOLO(`yolov8n.pt`)를 그대로 사용 중이다.
- **검증은 로직 검증까지만 완료됐다.** 테스트 33개는 가짜 검출기로 카운팅·필터·집계 로직을 확인한 것이며, 실제 지하철 환경에서의 정확도를 확인한 것은 아니다.
- 실제 YOLO 실행은 ultralytics 예제 이미지(bus.jpg) 1장으로 동작만 확인했다. (노트북 CPU 기준 프레임당 약 66ms)

---

## 1. 모델 선정

이 제품에는 두 종류의 모델이 필요하다.

| 구분 | 위치 | 역할 | 선정 모델 |
|---|---|---|---|
| 비전 모델 | 엣지 (Jetson) | 개찰구 통과 인원 카운팅 | YOLO 경량 모델 + ByteTrack + 이중 통과선 |
| 예측 모델 | 클라우드 | 10분·30분 후 혼잡도 예측 | LightGBM |

### 1.1 비전 모델: 검출 + 추적 방식

영상으로 인원을 세는 방식은 크게 두 가지다.

| 방식 | 대표 모델 | 장점 | 단점 |
|---|---|---|---|
| 검출 + 추적 | YOLO + ByteTrack | 한 명씩 구분, 이동 방향 판별 가능 | 극심한 밀집에서 겹침 발생 |
| 밀도 맵 | CSRNet 등 | 수천 명 밀집 상황에 강함 | 이동 방향을 알 수 없음 |

**선정: 검출 + 추적 방식**
- 개찰구는 입장·퇴장 방향을 구분해야 한다.
- 개찰구 구조상 승객이 한 줄씩 통과하므로 개별 검출이 가능하다.

**모델 크기: YOLO nano(n)로 시작, 부족하면 small(s)과 비교**
- 엣지 장비에서 카메라 여러 대를 실시간 처리해야 하므로 경량 모델이 필요하다.

### 1.2 현재 모델의 한계: 탑뷰 시점

- 현재 사용 중인 `yolov8n.pt`는 COCO 데이터셋으로 학습됐다.
- COCO의 사람 이미지는 대부분 옆이나 정면에서 촬영된 것이다.
- 개찰구 카메라처럼 천장에서 내려다보는 시점(탑뷰)에서는 머리와 어깨만 보이므로, 사전학습 모델이 놓칠 가능성이 높다.

**대응**
- 현장 시점에 맞춘 추가 학습(파인튜닝)이 필요하다.
- 탑뷰라면 "사람 전체" 대신 **"머리" 검출**로 학습하는 방안을 검토한다. 머리는 사람끼리 붙어 있어도 잘 겹치지 않는다.

### 1.3 예측 모델: LightGBM

- 입력: 최근 인원 수, 시간대, 요일, 공휴일, 날씨, 행사 정보 등 표 형태 데이터
- 표 형태 데이터에서는 딥러닝보다 트리 기반 모델이 적은 데이터로도 성능이 좋고 빠르다.

## 2. 학습 계획

### 2.1 데이터 수집
1. **공개 데이터셋으로 시작**
   - 머리 검출: SCUT-HEAD, Brainwash
   - 밀집 상황 사람 검출: CrowdHuman
   - 사용 전 라이선스가 수업·연구 용도로 허용되는지 확인한다.
2. **현장 영상 추가**
   - 실제 역 촬영은 운영 기관 허가가 필요하다.
   - 초기에는 동의를 받은 인원이 강의실 출입문을 통과하는 장면을 위에서 촬영한다.
   - 현장 조사 체크리스트의 조건(피크·한산, 역광, 비 오는 날, 캐리어 등)이 고르게 포함되도록 수집한다.

### 2.2 라벨링
- 영상에서 1~2초 간격으로 프레임을 추출한다. (연속 프레임은 거의 같은 장면이라 의미가 적다)
- Roboflow, CVAT 등의 도구로 사람(또는 머리)에 박스를 표시한다.
- 초기 목표: 1,000~3,000장

### 2.3 데이터 분할
- 같은 영상의 프레임을 무작위로 학습·검증용으로 나누면, 거의 같은 장면이 양쪽에 들어가 점수가 실제보다 높게 나온다.
- **촬영 날짜 또는 장소 단위로 분할한다.**
  - 예: 월~목 영상은 학습, 금요일 영상은 테스트

### 2.4 학습
- 처음부터 학습하지 않고, COCO 사전학습 모델에서 이어서 학습(파인튜닝)한다.

```bash
yolo train model=yolov8n.pt data=data/gate.yaml epochs=100 imgsz=640
```

- 개발 노트북은 CUDA를 사용할 수 없어 CPU 학습이 매우 느리다.
- **Google Colab 무료 GPU로 학습**하고 결과 모델 파일만 받아온다.

### 2.5 배포용 변환
- 학습한 모델을 Jetson용 TensorRT(INT8)로 변환한다.
- 변환 과정에서 정확도가 떨어질 수 있으므로 **변환 후 다시 검증**한다.

## 3. 검증 방법

| 단계 | 확인 내용 | 기준 | 현재 상태 |
|---|---|---|---|
| 로직 검증 | 카운팅·필터·집계 로직 | 시나리오 테스트 통과 | ✅ 33개 통과, 예제 이미지 1장 실행 확인 |
| 검출 성능 | 모델이 사람을 잘 찾는지 | 테스트셋 mAP50, 정밀도·재현율 | ❌ 학습 전 |
| 카운팅 정확도 | 실제 인원과 숫자가 맞는지 | 수동 카운트 대비 95% 이상 (PRD KPI) | ❌ 실제 영상 필요 |
| 시스템 성능 | 엣지 장비 실시간 처리 | Jetson에서 카메라당 10fps, 24시간 안정 동작 | ❌ Jetson 필요 |
| 예측 정확도 | 10분 후 혼잡도 예측 | MAPE 15% 이하 | ❌ 누적 데이터 필요 |

### 3.1 가장 중요한 지표: 카운팅 정확도
- 검출 점수(mAP)가 높아도 추적이 끊기면 숫자가 틀린다.
- 최종 판단은 **"실제 통과 인원 대비 몇 명으로 셌는가"**로 한다.
- 측정 방법은 `report/preprocess.md` 4장을 따른다.
  - 시간대·입장/퇴장별로 따로 측정
  - 오검출과 누락을 분리해서 기록
  - 전처리를 하나씩 추가하며 정확도 변화 기록

### 3.2 비교 기준
| 모델 | 비교 대상 |
|---|---|
| 비전 모델 | 학습 전 yolov8n vs 파인튜닝 후 모델 |
| 예측 모델 | 지난주 같은 시간 인원을 그대로 예측값으로 쓰는 방법 vs LightGBM |

---

## 4. 요약

> 모델은 YOLO 경량 모델 + ByteTrack으로 선정했다. 이동 방향 구분이 필요하고 엣지 장비에서 실시간 처리해야 하기 때문이다.
> 현재는 사전학습 모델로 파이프라인 로직을 검증한 단계이며, 다음 단계는 탑뷰 환경에 맞춘 파인튜닝과 수동 카운트 대비 95% 정확도 검증이다.
