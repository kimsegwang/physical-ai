# 지하철 개찰구 혼잡도 예측 – 전처리 설계 가이드

> 현장 조사 체크리스트 결과에 따라 적용하는 **조건부 기준표**입니다.
> 체크리스트에서 해당 항목에 체크한 결과에 맞춰 해당 줄만 골라 적용합니다.
>
> 구현: `src/subway_edge/` (설정 기본값은 `configs/default.json`).
> 구현하면서 처음 가이드와 달라진 부분은 **6장**에 이유와 함께 정리했습니다.

**시스템 전제**
- 개찰구 카메라 영상을 역사 내 엣지 AI 박스(Jetson급)에서 처리
- YOLO 경량 모델 + ByteTrack으로 사람 검출·추적
- 이중 통과선(line crossing) 방식으로 입·퇴장 인원 카운트
- 얼굴 인식 없음, 영상은 처리 후 폐기

---

## 1. 전처리 단계 (적용 순서 + 근거 항목)

| 순서 | 단계 | 적용 조건 (체크리스트 항목) | 하는 일 |
|---|---|---|---|
| 1 | 프레임 리사이즈·샘플링 | 항상 | 입력 크기를 맞추고 처리 프레임 수를 줄여 카메라 10대를 동시에 감당 |
| 2 | 영상 안정화 | 1-5가 "자주 흔들림" | 흔들림 보정. "약간"이면 생략하고 통과선 간격을 넓혀 대응 |
| 3 | ROI 크롭 + 고정 마스킹 | 항상 (1-3, 1-4, 3-1~3-4로 범위 결정) | 개찰구 영역만 남기고 광고판·유리·반사 바닥·에스컬레이터를 가림 |
| 4 | 밝기 깜빡임 보정 | 2-1이 "형광등" 또는 "혼합" | 프레임 평균 밝기를 직전 프레임들과 맞춤 |
| 5 | 명암 보정 (CLAHE) | 2-2가 "어두움/구역별 차이 큼", 2-3이 "있음" | 어두운 부분과 역광 실루엣을 살림 |
| 6 | 사람 검출 + 결과 필터 | 항상 (1-1, 1-2, 5-1, 6-1, 6-2로 값 결정) | 신뢰도·NMS·클래스·박스 크기 기준으로 오검출 제거 |
| 7 | 추적 (ByteTrack 방식) | 항상 (4-3, 5-2, 5-3으로 값 결정) | 같은 사람에게 같은 ID 부여. 고신뢰도 검출로 1차 매칭, 저신뢰도 검출로 2차 매칭 |
| 8 | 카운팅 후처리 | 항상 (4-1, 4-2, 5-4로 방식 결정) | 이중 통과선, 방향 판별, ID당 1회 카운트, 짧은 궤적 제거 |
| 9 | 집계값 이상치 처리 | 항상 | 1분 집계에서 개찰구 물리 한계를 넘는 값만 잘라내고, 급증은 값을 그대로 두고 플래그만 붙임 |

**처리 흐름**

```
프레임 입력
  → 리사이즈·샘플링
  → (흔들림 있으면) 영상 안정화
  → ROI 크롭 + 고정 마스킹
  → (형광등이면) 깜빡임 보정
  → (어둡거나 역광이면) CLAHE
  → YOLO 사람 검출 + 결과 필터
  → ByteTrack 방식 추적
  → 이중 통과선 카운팅
  → 1분 집계 + 이상치 처리 (한계 초과 잘라내기, 급증 플래그)
  → 클라우드 전송 (숫자만, Publisher 인터페이스)
```

**순서가 중요한 이유**
마스킹을 먼저 해야 이후 단계의 연산량이 줄고, 광고판처럼 밝은 영역이 명암 보정 계산을 왜곡하지 않는다.

## 2. 주요 파라미터 초기 추천값

| 파라미터 (설정 키) | 기본값 | 조사 결과에 따른 조정 |
|---|---|---|
| 입력 해상도 (`preprocess.input_size`) | 640px (긴 변) | 1-1이 4m 이상이라 사람이 작게 보이면 960px (대신 처리 fps 감소). 작은 영상은 키우지 않음 |
| 처리 fps (`preprocess.process_fps`) | 카메라당 10fps | 8~10fps. 보행 속도 기준 통과 구간에서 8프레임 이상 잡히면 충분 |
| ROI·마스크 (`preprocess.roi`, `masks`) | 개찰구 앞뒤 각 1~1.5m만 포함 | 3-1 "심한 반사" → 바닥 반사 영역 추가 마스크 / 3-3 "영상 재생" → 광고판 반드시 마스크 |
| 젖은 바닥 마스크 (`preprocess.wet_floor_masks`) | 없음 | 비·눈 오는 날 반사가 생기는 바닥 영역을 현장에서 미리 지정. 날씨가 비·눈이면 자동으로 추가됨 |
| 통과선 위치 (`counting.gates`) | 개찰구 출구 쪽 끝에서 30~50cm 바깥, **선 2개**를 40~50cm 간격으로 | 두 선을 순서대로 지나야 1명 카운트 / 1-5 흔들림 있으면 간격 60cm 이상 |
| 검출 신뢰도 임계값 (`detection.conf_threshold`) | 0.4 | 새 트랙 생성·1차 매칭 기준. 5-1 "혼잡 이상" → 0.3~0.35 (누락 방지) / 2-4 진한 그림자·3-1 심한 반사 → 0.5 |
| 저신뢰도 하한 (`detection.low_conf_threshold`) | 0.1 | 0.1~0.4 검출은 버리지 않고, 이미 추적 중인 사람을 이어 붙이는 2차 매칭에만 사용 |
| NMS IoU 임계값 (`detection.nms_iou`) | 0.5 | 5-2 "덩어리로 몰림" → 0.6~0.65 (겹친 사람을 지우지 않게) / 탑뷰 + 여유 → 0.45 |
| 클래스 필터 (`detection.aux_classes`) | person만 카운트 | 6-1에서 캐리어 많음 → 해당 클래스는 카운트 제외 확인용으로만 검출 (COCO에 유모차 클래스는 없음) |
| 최소 박스 크기 (`detection.min_area_ratio`) | 현장 영상에서 잰 성인 평균 박스 면적의 35% | 6-2 "많음" → 25% / 1-2 비스듬한 각도면 화면 위·아래 기준 면적을 따로 주고 위치에 따라 보간 |
| 최대 박스 크기 (`detection.max_area_ratio`) | 성인 평균의 2.5배 | 6-3 "두꺼운 외투" 계절에 3배로 상향 |
| 추적 버퍼 (`tracking.track_buffer`) | 30프레임 (약 3초) | 5-3 "자주 멈춤" → 50프레임 / 4-3 "좁음" → 40프레임 |
| 추적 매칭 IoU 하한 (`tracking.match_iou_min`) | 0.2 | 낮출수록 느슨하게 이어 붙임. 5-2 "덩어리" → 0.15 (ID 끊김 줄이기) |
| 최소 궤적 길이 (`counting.min_track_len`) | 5프레임 | 반사·광고판 오검출이 남으면 8프레임 |
| 중복 카운트 방지 (`counting.recount_block_sec`) | 같은 ID는 방향별 1회만 카운트, 재카운트 금지 5초 | 개찰구 단위 쿨다운은 쓰지 않기 (5-4 꼬리물기 시 두 번째 사람이 누락됨) |
| CLAHE (`preprocess.clahe_mode`) | off / on / auto, clipLimit 2.0, 타일 8×8 | 2-3 "항상 역광" → on, clipLimit 3.0 / "특정 시간대만" → auto |
| 개찰구 물리 한계 (`aggregation.gate_limit_per_min`) | 게이트·방향당 60명/분 | 넘는 값은 잘라내고 `clipped_in/out` 플래그. 개찰구 유형(4-1)별 실처리량을 보고 조정 |
| 급증 플래그 (`aggregation.spike_*`) | 직전 15분 중앙값의 3배 이상이면서 차이 10명 이상 | 값은 바꾸지 않고 `spike_in/out` 플래그만 붙임 |

> **박스 크기 기준 잡는 법**
> 카메라 높이와 해상도마다 사람 크기가 달라서 절대값(px)보다 비율로 정하는 것이 좋다.
> 현장 영상에서 성인 10명 정도의 박스를 재고, 그 평균을 기준으로 잡는다.

## 3. 엣지 장비 기준 필수 / 조건부 / 생략

### 3.1 꼭 필요한 것
| 항목 | 이유 |
|---|---|
| 리사이즈 | 카메라 10대 동시 처리를 위한 기본 조건 |
| ROI 크롭·마스킹 | 오검출 감소 + 오히려 연산량을 줄여줌 |
| 검출 결과 필터 (신뢰도·NMS·클래스·크기) | 연산 부담 거의 없고 정확도 효과가 큼 |
| 추적 | 같은 사람 중복 카운트 방지의 기본 |
| 이중 통과선 카운팅 | 선 근처에서 흔들리는 사람의 중복 카운트 방지 |
| 최소 궤적 길이 | 반사·광고판 등 순간 오검출 제거 |

### 3.2 조건부로 넣을 것
| 항목 | 연산 부담 | 적용 조건 |
|---|---|---|
| 깜빡임 보정 | 가벼움 | 형광등 환경 |
| CLAHE | GPU 처리 시 적음 | 어두움·역광 |
| 영상 안정화 | 상대적으로 무거움 | 흔들림이 자주 있는 현장만 |

### 3.3 생략해도 되는 것
| 항목 | 생략 이유 / 대체 방법 |
|---|---|
| 프레임 전체 원근 변환 (warp) | 무겁고 영상이 왜곡됨 → 화면 위치별로 박스 크기 기준을 다르게 주는 방식으로 대체 |
| 그림자 제거 알고리즘 | YOLO 기반에서는 비용 대비 효과 낮음 → 신뢰도 임계값 + 최소 궤적 길이로 대응 |
| 배경 차분 | 딥러닝 검출을 쓰므로 불필요 |
| 노이즈 제거 필터 | 대부분 불필요 → 먼지가 많으면(8-4) 렌즈 청소 주기를 정하는 것이 더 효과적 |

## 4. 정확도 95% 검증 방법

### 4.1 측정량 확보
- 피크와 비피크 각각 **누적 15분 이상, 통과 인원 300~500명 이상** 측정
- 수동 카운트도 틀릴 수 있으므로 두 사람이 따로 세거나, 녹화 영상을 느리게 재생하며 센다
- 실제 역 녹화는 운영 기관의 허가와 개인정보 처리 절차가 필요하다

### 4.2 정확도 계산
```
정확도 = 1 − |AI 카운트 − 수동 카운트| ÷ 수동 카운트
```
- **입장·퇴장별, 시간대별로 따로** 95% 이상인지 확인한다
- 전체 합계만 보면 피크 때의 누락과 한산할 때의 오검출이 서로 상쇄되어 실제보다 좋게 나올 수 있다

### 4.3 오류 유형 분리
- 최소 한 구간은 통과 이벤트를 한 명씩 맞춰본다
- 오검출(없는 사람을 셈)과 누락(있는 사람을 놓침)이 각각 몇 건인지 분리된다
- 오검출이 많으면 신뢰도 임계값을 올리고, 누락이 많으면 내린다

### 4.4 단계별 효과 기록
전처리를 하나씩 추가하며 정확도 변화를 표로 남긴다.

| 단계 | 정확도 | 오검출 | 누락 |
|---|---|---|---|
| 기본 (전처리 없음) | __% | __건 | __건 |
| + ROI·마스킹 | __% | __건 | __건 |
| + CLAHE | __% | __건 | __건 |
| + 이중 통과선 | __% | __건 | __건 |
| + 파라미터 조정 | __% | __건 | __건 |

> 각 전처리 단계가 왜 필요한지 보고서에서 숫자로 증명할 수 있다.

## 5. 시간대·날씨별 설정 차이

프로필은 값을 덮어쓰지 않고 **조정 방향만** 정한다. 현장에서 이미 더 강하게 맞춘 값은 그대로 둔다.
- `{"at_least": v}` → max(현장값, v)
- `{"at_most": v}` → min(현장값, v)

예) 현장 추적 버퍼가 50(5-3 "자주 멈춤")이면 피크가 되어도 40으로 내려가지 않고 50을 유지한다.

### 5.1 시간대(혼잡도)별
| 상황 | 설정 (프로필) |
|---|---|
| 피크 (peak) | 신뢰도 at_most 0.35, NMS at_least 0.6, 추적 버퍼 at_least 40, 매칭 IoU 하한 at_most 0.15 → 밀집 상황 누락 감소 |
| 평시 (normal) | 현장 설정 그대로 |
| 한산·야간 (quiet) | 신뢰도 at_least 0.45 → 그림자·반사 오검출 감소 |
| 특정 시간대 역광 | 시계 기준이 아니라 **프레임 평균 밝기를 보고 CLAHE 자동 전환** (`clahe_mode: auto`, 계절 변화에도 안전) |

**혼잡도 전환 기준**: 직전 1분 집계의 **게이트당 분당 인원**(입장+퇴장 ÷ 게이트 수)

| 현재 상태 | 전환 조건 |
|---|---|
| 평시 → 피크 | 게이트당 10명 이상 |
| 피크 → 평시 | 게이트당 7명 미만 |
| 평시 → 한산 | 게이트당 1명 이하 |
| 한산 → 평시 | 게이트당 2명 이상 |

전환 기준과 복귀 기준을 다르게 둬서(히스테리시스) 경계값 근처에서 설정이 매분 바뀌지 않게 한다.

### 5.2 날씨별
| 상황 | 설정 |
|---|---|
| 비·눈 | 젖은 바닥 반사 증가 → 현장에서 지정한 `wet_floor_masks`를 마스크에 추가, 최소 궤적 길이 at_least 8프레임 |
| 우산 | 탑뷰에서 사람을 가림 → 조사 시 "우산을 어디서 접는지" 확인해 통과선 위치 판단, 장기적으로 비 오는 날 영상을 학습 데이터에 추가 |
| 겨울 (외투) | 외투로 박스가 커짐 → 최대 박스 크기 at_least 3배 |

적용 순서: 현장 설정 → 혼잡도 프로필 → 날씨 프로필 → 외투 프로필

### 5.3 자동 전환 구조
```
[클라우드] 날씨 API 수신 → 엣지에 set_weather(condition, heavy_coat) 호출
           (condition: clear / cloudy / rain / snow)
[엣지]    프레임 밝기·직전 1분 게이트당 인원 측정 → CLAHE·혼잡도 프로필 자동 전환
```

## 6. 구현하면서 바뀐 부분 (처음 가이드 대비)

| 항목 | 처음 가이드 | 구현 | 바꾼 이유 |
|---|---|---|---|
| 추적 매칭 기준 | 매칭 임계값 0.8, 덩어리 → 0.7 | IoU 하한 `match_iou_min` 0.2, 덩어리(피크) → 0.15로 **낮춤** | 0.8은 비용(1−IoU) 상한이라 0.7로 낮추면 오히려 엄격해져 ID가 더 끊긴다. 인원만 세므로 ID 뒤바뀜보다 ID 끊김(통과 기록 손실)이 더 큰 문제 |
| 검출 신뢰도 0.4의 의미 | 0.4 미만은 버림 | 0.4는 새 트랙 생성·1차 매칭 기준, 0.1~0.4는 2차 매칭에만 사용 | 가려져서 점수가 낮아진 사람을 놓치지 않으면서, 낮은 점수만으로는 새 사람을 만들지 않게 하려고 (ByteTrack 방식) |
| 혼잡도 전환 | 직전 1분 카운트 기준 | 게이트당 분당 인원 기준 (피크 10 / 해제 7, 한산 1 / 해제 2) | 카메라마다 비추는 개찰구 수가 달라 카메라 합계로는 같은 기준을 쓸 수 없다 |
| 집계 이상치 | 튀는 값을 전송 전 보정 | 물리 한계 초과만 잘라내고, 급증은 값 유지 + 플래그 | 경기 종료 같은 진짜 급증을 지우면 안 되며, 판단은 이력이 있는 클라우드가 하는 편이 낫다 |
| 시간대·날씨 프로필 | 상황별 절대값 (예: 피크 신뢰도 0.35) | at_least / at_most로 방향만 지정 | 절대값이면 현장에서 더 강하게 맞춘 값(예: 추적 버퍼 50)이 피크 때 오히려 약해진다 |
| 반사 마스크 확대 | 비·눈이면 마스크 영역 확대 | 현장에서 지정한 `wet_floor_masks`를 추가 | 반사가 생기는 위치는 현장마다 달라 자동 확대보다 미리 지정하는 편이 정확하다 |
