Models

6개 모델의 기능과 사용 예시

코드는 동작 방식을 보여주는 요약본입니다. 좌표는 0~1 정규화 좌표로 다루고, 프레임은 파일로 저장하지 않습니다.

YOLOE

텍스트·이미지로 클래스를 정하는 실시간 YOLO · 칭화대 2025
보조 · 엣지 시험
  • chevron_right텍스트 프롬프트: "stroller"처럼 이름만 주면 그 클래스를 검출
  • chevron_right비주얼 프롬프트: 예시 박스로 "이런 물체" 찾기, 프롬프트 없이 전체 검출도 가능
  • chevron_right클래스를 고정하면 일반 YOLO처럼 TensorRT로 내보낼 수 있음 (ultralytics 포함)
model = YOLOE("models/yoloe-11s-seg.pt")
names = ["person", "stroller", "wheelchair"]
model.set_classes(names, model.get_text_pe(names))
results = model.predict(frame, conf=0.4)

우리 프로젝트에서: COCO에 없는 유모차·휠체어를 카운트 제외 확인용 보조 클래스로 시험할 때 씁니다.

DINO-X

오픈월드 객체 이해 통합 모델 · IDEA Research 2024
제한적 · 클라우드
  • chevron_right이름 없이도 화면 속 물체를 모두 찾는 프롬프트 없는 검출
  • chevron_right박스와 함께 마스크·사람 키포인트·영역 설명 문장까지 출력
  • chevron_right가중치 비공개, 유료 클라우드 API로만 사용
client = Client(Config(os.environ["DDS_API_TOKEN"]))
task = V2Task(api_path="/v2/task/dinox/detection",
    api_body={"model": "DINO-X-1.0", "image": url,
              "prompt": {"type": "text", "text": "person"}})
client.run_task(task)

우리 프로젝트에서: 이미지가 외부 서버로 가므로 운영 영상에는 쓰지 않습니다. 허가된 공개 데이터셋에서 성능 비교 기준선으로만 씁니다.

SAM 3

개념 프롬프트로 모든 인스턴스를 분할·추적 · Meta 2025
보조 · 오프라인
  • chevron_right"person" 같은 짧은 명사구로 해당하는 모든 물체의 마스크·박스를 생성
  • chevron_right영상에서는 같은 물체에 같은 ID를 유지하며 추적
  • chevron_right대형 모델이라 서버 GPU가 필요하고, 가중치는 접근 승인 후 다운로드
processor = Sam3Processor(build_sam3_image_model())
state = processor.set_image(image)
out = processor.set_text_prompt(state=state, prompt="person")
masks, boxes, scores = out["masks"], out["boxes"], out["scores"]

우리 프로젝트에서: 학습용 라벨 초안을 자동으로 만들고 사람이 검수합니다. 개발 PC에 GPU가 없어 Colab에서 돌리므로 촬영 동의 범위 안에서만 씁니다.

SigLIP / SigLIP 2

이미지·텍스트 임베딩 모델 · Google
보조 · 저빈도
  • chevron_right학습 없이 문장 후보 중 이미지와 가장 맞는 것을 고르는 제로샷 분류
  • chevron_right임베딩 유사도로 장면 검색·비교
  • chevron_rightsigmoid 점수라 여러 상태가 동시에 참일 수 있음
clf = pipeline("zero-shot-image-classification",
               model="google/siglip2-base-patch16-224")
clf(image, candidate_labels=["a clear view of ticket gates",
    "a camera view blocked by an object", "a wet reflective floor"])

우리 프로젝트에서: 1분에 한 번 카메라 가림·암전·젖은 바닥을 판단해, 카운트 0이 "사람이 없어서"인지 "카메라 문제"인지 구분합니다.

OCR

이미지 속 글자 읽기 · EasyOCR, PaddleOCR 등
보조 · 검증
  • chevron_right글자 영역을 찾고 읽어 텍스트 + 위치 + 신뢰도를 출력
  • chevron_rightEasyOCR은 설치가 간단하고, PaddleOCR은 경량 모델과 한국어 성능이 좋음
  • chevron_right작은 영역만 읽으면 엣지에서도 가볍게 실행
reader = easyocr.Reader(["ko", "en"])
OSD_ROI = (0.0, 0.0, 0.35, 0.08)  # 0~1 정규화 좌표
crop = frame[:int(0.08 * h), :int(0.35 * w)]
text = " ".join(t for _, t, c in reader.readtext(crop) if c > 0.5)

우리 프로젝트에서: 검증 영상의 화면 시각(OSD)을 읽어 수동 카운트와 분 단위로 맞춥니다. 교통카드처럼 개인 정보가 담긴 글자는 읽지 않도록 영역을 한정합니다.

MediaPipe

온디바이스 비전 솔루션 모음 · Google
보조 · 비식별화
  • chevron_right얼굴 검출, 포즈(관절 33개), 손, 물체 검출, 사람/배경 분리
  • chevron_rightTFLite 기반이라 CPU에서도 빠름
  • chevron_right가까운 정면 사람 기준이라 천장 시점의 작은 다수 인원에는 약함
detector = vision.FaceDetector.create_from_options(options)
result = detector.detect(mp.Image(image_format=mp.ImageFormat.SRGB, data=rgb))
for det in result.detections:
    b = det.bounding_box  # 이 영역을 메모리에서 블러 (저장 없음)

우리 프로젝트에서: 검증 영상을 사람이 볼 때 얼굴을 흐리게 처리합니다. 작은 얼굴은 놓칠 수 있어 사람 박스 윗부분 블러와 함께 씁니다.

Why YOLOv8n + ByteTrack

왜 지금 모델이 더 적합한가

개찰구 카운팅 검출기가 반드시 지켜야 하는 조건 네 가지로 비교했습니다.

기준 1 엣지 실시간 Jetson 한 대가 카메라 10대 × 10fps, 초당 100프레임을 처리해야 합니다. nano급이 필요합니다.
기준 2 한 명씩 추적 입장·퇴장 방향을 가리려면 매 프레임 사람마다 박스가 나와 추적기로 이어져야 합니다.
기준 3 영상은 역 안에서만 제품은 프레임을 외부로 보내지 않고 숫자만 전송합니다. 클라우드 API 모델은 쓸 수 없습니다.
기준 4 사람 한 클래스 세는 대상은 사람뿐입니다. COCO의 person은 가장 많이 학습된 클래스라, 오픈 어휘 모델의 장점이 크지 않습니다.
모델 엣지 실시간 한 명씩 추적 외부 전송 없음 사람 검출 결론
YOLOv8n + ByteTrack (현재) ○ nano급 ○ ○ ○ COCO person 채택
YOLOE △ s급부터라 더 무거움 ○ ○ = 이점 없음 보조 클래스 시험용
DINO-X ✕ 클라우드 API △ 호출 지연 ✕ ○ 강함 공개 데이터 비교 기준선
SAM 3 ✕ 대형 모델 ○ 마스크 + ID ○ 로컬 GPU 필요 ○ 강함 오프라인 라벨 생성
SigLIP △ 저빈도만 ✕ 검출 불가 ○ ✕ 카메라 상태 점검
OCR △ 작은 영역만 ✕ ○ ✕ 검증 시간 동기화
MediaPipe ○ CPU 가능 △ 가까운 정면 위주 ○ △ 천장 시점에 약함 검증 화면 얼굴 블러

표는 공개 자료 기준이며 우리 영상으로 잰 값이 아닙니다. 공개된 YOLOE의 최소 크기(s급)도 최신 버전에서 다시 확인이 필요합니다.

conversion_path
배포 경로가 이미 있음 ultralytics에서 Jetson TensorRT(FP16·INT8) 변환이 바로 되고, ByteTrack 방식 추적과 이중 통과선이 이 검출기 기준으로 구현돼 있습니다.
fact_check
로직 검증을 마친 구조 세기·추적·집계·설정 전환을 시나리오 테스트 33개로 확인했습니다. 검출기를 바꾸면 신뢰도·박스 크기 기준을 다시 재야 합니다.
trending_up
개선은 파인튜닝으로 현장 정확도가 부족하면 모델을 바꾸기보다 동의받은 현장 영상으로 같은 YOLO를 파인튜닝합니다. 후보는 YOLOv8n · YOLO11n · YOLO26n입니다.
